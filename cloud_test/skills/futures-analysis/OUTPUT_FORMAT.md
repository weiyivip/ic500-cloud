# IC500期货分析输出格式

## 输出结构说明

本文件定义了IC500期货分析的所有输出格式，包括盘中和盘后两种场景。

**核心要求：所有分析结论必须引用证据**
- 每个判断至少引用2个JSON字段作为证据
- **交易建议必须引用至少4个不同类型字段**（2技术+1资金+1风控）
- 必须使用完整字段路径（如 `multi_period_features.60min.macd.status`）
- 不得凭经验推断，必须基于实际数据
- **证据不足时必须输出**："证据不足，维持观望"
- 参见SKILL.md中的"证据引用规范"

---

## 输出复杂度策略（重要）

### 实时输出策略（盘中：09:30-11:30, 13:00-15:00）

**目标**：优先保证响应速度，而不是可视化效果。

**禁止生成任何复杂可视化内容**，包括但不限于：
- SVG 图表
- Mermaid 流程图
- ASCII 图
- 折线图代码（如 Chart.js、ECharts）
- 柱状图代码
- 任何需要大量数据点组织的图形描述

**允许**：
- Markdown 表格
- 项目符号列表
- 文本摘要
- 简单数值对比

**重要**：除非用户明确要求生成图表，否则盘中分析默认采用纯文本输出。

---

### 盘后输出策略（15:00之后）

**目标**：在保证理解效果的前提下，优先使用简洁输出。

**规则**：
- 仅在图表能够明显提升理解效果时生成
- 默认仍优先使用文本和 Markdown 表格
- 让模型自行判断图表是否有价值

**示例**：
- ❌ **不必要的图表**：趋势=上涨概率65%、支撑=5950、压力=6030 → 纯文本足够
- ✅ **有价值的图表**：复杂的多周期共振分析、历史回测数据对比 → 图表辅助理解

---

## 置信度与仓位对照表（机构标准）

**置信度判定规则**：
- 根据证据数量和信号验证通过率，判定结论置信度
- 置信度直接影响建议仓位大小

| 置信度 | 证据数量 | 信号验证 | 建议仓位 | 说明 |
|--------|----------|----------|----------|------|
| **高置信度** | ≥8项 | ≥5项通过 | 重仓（2-3手） | 多维度共振，可加大仓位 |
| **中置信度** | 5-7项 | ≥3项通过 | 轻仓（1手） | 信号较明确，但需谨慎 |
| **低置信度** | 4项（最低） | ≥3项通过 | 试探仓（0.5手） | 刚好满足最低标准，轻仓试水 |
| **证据不足** | <4项 | - | **强制观望** | 触发 Priority 2，禁止交易 |

**重要说明**：
- 置信度仅影响仓位，不影响方向（方向由五层周期决定）
- 高置信度仍需满足 Priority 3（风控），止损/盈亏比不满足时降级
- 置信度必须在第一屏显式输出（如：**置信度：高**）

**示例**：
- 证据数量：8项（180min MA、60min MA、30min MACD、60min RSI、持仓变化、北向资金、止损、盈亏比）
- 信号验证：5项通过（趋势、成交量、持仓、MACD、RSI）
- 置信度：**高**
- 建议仓位：2手

## 一、盘中输出格式（09:30-11:30, 13:00-14:30）

### 第一屏：当前决策（最重要）

- **当前决策**：【做多 / 做空 / 观望】
- **置信度**：【高 / 中 / 低 / 证据不足】
  - **证据数量**：X项（列出字段名称）
  - **信号验证**：X/5项通过
  - **建议仓位**：X手（根据置信度对照表）
- **胜率概率分布**：上涨 A% | 下跌 B% | 震荡 (100-A-B)%
  - **计算规则**：先确定上涨概率A和下跌概率B，震荡概率=100-A-B
  - **禁止**：三次独立生成（容易导致总和≠100%）
  - **示例**：若判断上涨55%、下跌30%，则震荡=100-55-30=15%
- **实盘参考参数（合约：持有合约代码）**：
  - **建议入场区间**：XXXX - XXXX 点
  - **强制风控止损**：XXXX 点（*算式校验：当前 ATR=XX，最低止损要求=XX点，实际设置=XX点（合规/不合规）*）
    - **ATR 缺失时**：XXXX 点（*固定止损 XX 点，【因 ATR 缺失启用固定点数止损】*）
  - **目标止盈位置**：XXXX 点
  - *价格折算过程：主力参考价 (XXXX) - 基差 (XX点) = 持有合约执行价 (XXXX)*

**重要**：
- 必须显式展示置信度、止损校验算式和价格折算过程，避免LLM计算错误
- 若 JSON 缺失 ATR，必须启用固定点数止损并显式注明【因 ATR 缺失启用固定点数止损】

## 三、语言要求

- 语言精炼，直击要害，避免空泛描述
- 决策汇总必须放在最前面，后续详细分析作为支撑
- 严禁使用"后市观察"、"密切关注"、"视情况而定"等模糊词汇
- 若必须观察，请具体到"观察区间XX-XX的收盘价稳定性"或"观察XX点位的突破/跌破情况"

---

## 四、核心要求

- 所有价格单位为指数点，成交量为手数，时间为北京时间（UTC+8）
- 所有分析必须基于提供的数据，不得臆测
- 必须严格遵守TRADING_RULES.md中的决策优先级、尾盘硬锁、止损校验等风控铁律
